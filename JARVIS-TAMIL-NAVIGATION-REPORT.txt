Original findings:
1. The active fixed map had five pages and omitted Login.
2. Partial-keyword matching accepted overly loose phrases and missed requested
   Tamil transliterations, history, refresh, help and resume commands.
3. Session callbacks lacked a per-listening-cycle one-result latch, so duplicate
   or late results could conflict with processing/playback.
4. Repeated activation could cancel and restart in-progress setup or speech.
5. Manual reload and cached-page restoration did not have an explicit, single-use
   voice-navigation handoff. Old in-memory state could disagree with tab storage.
6. Native recognition assumed a well-formed results collection; malformed events
   could throw. A backend callback's existence was mistaken for recognition
   availability even when the provider was not configured.
7. Tamil synthesis already selected Tamil correctly; the observed missing sound
   is a missing engine/configuration issue. Only Microsoft David, Mark and Zira
   (en-US) were exposed. No Tamil engine was installed during this upgrade.
8. The local preview and project database were stopped at inspection. Restarted
   the existing isolated PostgreSQL instance on 127.0.0.1:55432 and preview.

HOW TO START AND CONFIGURE

In PowerShell:
  Set-Location 'C:\Users\Admin\OneDrive\Desktop\MVR_Website'
  npm start

npm start is the existing verified package script for backend/server.js.
npm run dev is the existing watch-mode command. This QA session ran the existing
preview instead, which does not run migrations, seed data or outbound workers:
  node --env-file-if-exists=.env scripts/preview-server.js

The preview is running at http://localhost:3000/. Do not start another server
on port 3000 simultaneously. Existing .env/database settings were not changed.
No production database was used by the automated tests; their setup checks that
TEST_DATABASE_URL differs from DATABASE_URL and uses temporary test schemas.

Microphone:
1. Open the local site in a supported browser. Production must use HTTPS.
2. Open JARVIS and click Start voice mode. Allow microphone access for this site.
3. If previously denied, change this site's microphone permission in the browser
   site controls and reload; check Windows microphone privacy access if needed.
4. Wait for the introduction to finish. Speak only when the indicator is Listening.
5. Stop speaking pauses the cycle; Resume restarts it. Mic off disables voice mode.
   Click Resume after a stop, tab hiding, a manual reload or a recoverable error.

Tamil browser voice:
Open Windows Settings > Time & language > Speech > Manage voices/Add voices
(labels may vary), or Tamil's Language options. Install Tamil text-to-speech only
if offered. Microsoft lists Valluvar for Tamil. Restart the browser, then check
speechSynthesis.getVoices() for ta-IN or another ta locale. A general language
pack or an English speech-recognition pack is not evidence of Tamil TTS support.
An OS/Narrator voice may not be exposed to a particular browser. No software or
voice pack was installed by this upgrade.

Existing Azure alternative (previously approved integration):
Privately configure the existing .env with a valid Azure Speech resource key and
its matching region:
  AZURE_SPEECH_KEY=<your resource key>
  AZURE_SPEECH_REGION=<your resource region>
  AZURE_SPEECH_VOICE=ta-IN-ValluvarNeural
The existing allowed alternative is ta-IN-PallaviNeural. Never put the key in
frontend code or chat. Restart the backend and reload the page after saving.
The provider notice must show Azure before activation. Resource usage follows
your existing Azure plan. No new provider or account was introduced here.
The public config should report cloud_speech_available and
cloud_recognition_available as true. OpenAI is optional for answer generation;
it is not required for command navigation or website-based Tamil answers.
See JARVIS-TAMIL-AZURE-SETUP.txt for the existing SDK/configuration details.

Recognition must already be listening to hear a command. The Resume command is
understood during an active recognition cycle; it cannot reactivate a physically
stopped microphone. Use the button in that situation. While JARVIS is speaking,
recognition is intentionally stopped to prevent feedback; interrupt with the
Stop speaking button. Hey JARVIS is an optional prefix, not an always-on wake word.
Matching recognized text is tested; actual Tamil/Tanglish acoustic accuracy is
provider/device dependent and has not been established in this session.

REMAINING LIMITATIONS AND MANUAL ACCEPTANCE

1. Install/expose a Tamil TTS voice or configure the existing Azure service, then
   manually verify the introduction, a spoken MVR question, a Tamil page command,
   a Tanglish command, end-of-speech listening resumption and post-navigation
   behavior on the actual intended browser/device. Repeat on mobile hardware.
2. Test fresh permission grant/denial and disconnected microphone hardware.
3. Native recognition stays ta-IN. There is no silent English-locale fallback;
   an English pack does not provide Tamil recognition. Dialect/accent coverage
   and code-switching accuracy depend on the recognition provider.
4. The current site's Referrer-Policy: no-referrer causes cross-document history
   entries to expose null URLs in the tested browser. JARVIS deliberately refuses
   those Back/Forward commands. Say a page name instead. Security/privacy headers
   were preserved. Known, visible allowlisted history entries use traverseTo.
5. Browsers may require another Resume/Retry click after navigation or block
   autoplay/background capture. There is no promise of continuous background use.
6. A voice request for Login may trigger the site's normal authenticated redirect;
   the assistant never bypasses that flow and does not auto-listen on the resulting
   account/booking page outside its navigation allowlist.
