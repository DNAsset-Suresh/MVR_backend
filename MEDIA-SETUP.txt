Recommended next step — curated public posts, no credentials:
1. Open the official account and copy the public URL of each approved post or Reel.
2. In the existing Admin → Media editor, create an entry using that URL, its approved title/caption, and an approved thumbnail if available. Publish the entry.
3. The Media page recognises instagram.com/p/... and instagram.com/reel/... URLs and displays a card with an original-post link. Add a profile URL as a Media entry to manage the follow button through the CMS; the supplied account is the fallback.
4. Verify each post opens for the intended audience. This is a curated link gallery, not an automatic feed. No password, token, or Meta permissions are required.

If automatic feed retrieval is desired:
Use Meta's Instagram API with Instagram Login for a supported Business or Creator account. This route does not require a linked Facebook Page. Create/configure the Meta app, add an HTTPS OAuth redirect for the actual deployment domain, and authorise the account with the basic read permission (instagram_business_basic). Confirm the current access level and app-review requirements in the app dashboard for the accounts the app will serve; request no publishing/messaging permissions for a read-only feed.

A backend adapter must then be added to the existing Express app. Store the app secret and access token only in backend environment variables, use a supported version of graph.instagram.com, fetch only the needed media fields, cache results, refresh tokens securely, and return only captions, public URLs and thumbnails. Handle expired authorisation, rate limits, empty feeds and provider failures. These OAuth/feed components are not implemented or represented as connected in this update. Do not paste passwords or private tokens into chat or a frontend file.
