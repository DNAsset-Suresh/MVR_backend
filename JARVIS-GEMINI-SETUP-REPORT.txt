IMPLEMENTATION

The active voice endpoint now uses official @google/genai 2.30.0. GEMINI_MODEL defaults to gemini-3.5-flash-lite, documented by Google as a stable text-output model supporting structured output. It does not generate audio. Model/API compatibility was verified from current documentation and through the installed SDK with a mocked HTTP transport. Access for your particular Google account cannot be verified without a key.

Pipeline: Tamil recognition -> POST /api/assistant/voice -> approved website records + Gemini -> validated spoken text -> existing Tamil browser TTS or consented Azure synthesis. Browser recognition remains ta-IN; mixed English/Tamil transcription quality depends on the recognizer. A specifically requested English answer can use an installed English browser voice. This does not enable persistent bilingual recognition or switch Tamil cloud recognition to English.

The exact greeting is:
வணக்கம்! நான் MVR-ன் JARVIS உதவியாளர். உங்களுக்கு என்ன உதவி வேண்டும்?

Gemini receives only bounded question/history text and published records. JSON output permits answer, clarification or an approved navigation intent. A requested destination must also match the human's command; an enum alone is not sufficient. The frontend validates the action again and uses its own fixed route and confirmation. There are no Gemini tools for code, shell commands, SQL, external URLs or booking changes. Fast local commands remain deterministic.

Up to six question-and-answer turns live in server RAM for at most 30 minutes. A separate random HttpOnly voice cookie and authenticated owner isolate this context from legacy chat and other accounts. Mic off deletes context and aborts a pending reply when the server is reachable. An unreachable server retains context only until expiry. No audio or conversation text is written to files, application logs or PostgreSQL. Existing activation consent was versioned so the new disclosure appears before use.

“MVR பற்றி சொல்லு” followed by “அந்த பக்கத்தை திற” resolves the last verified topic. Unknown or ambiguous commands ask for clarification. Availability bypasses Gemini and reads current authorized public database data; today/tomorrow are calculated in Asia/Kolkata. Availability is never a booking confirmation.

Provider requests have bounded timeouts, output length, history and retries (one attempt, no automatic continuation). Invalid credentials, model/configuration errors, quotas, network errors and timeouts return a spoken Tamil website fallback. Raw provider errors and keys are not returned or logged. Source IDs must refer to supplied records. This reduces hallucination risk; it cannot prove every model sentence is factually faithful, so live-answer review remains necessary.

SECURE GEMINI SETUP

1. Create a Gemini API key privately through Google AI Studio: https://aistudio.google.com/apikey
2. Review your project's quota, billing and data terms first. No billing or paid service was enabled by this work. Current Gemini 3.5 Flash-Lite pricing lists a free tier subject to limits; paid standard rates are USD 0.30 per million input tokens and USD 2.50 per million output tokens. Unpaid-tier content may be used to improve Google products. Rates and eligibility can change: https://ai.google.dev/gemini-api/docs/pricing
3. Add only these entries to the existing .env, preserving all database and integration settings:
   GEMINI_API_KEY=<your private key>
   GEMINI_MODEL=gemini-3.5-flash-lite
   Replace the placeholder; never put the key in public files or paste it into chat.
4. Restart the existing backend. Run npm run jarvis:check. This prints configuration booleans and the model name, without exposing secrets or calling a provider.
5. Once you accept any usage cost, run npm run jarvis:check -- --live. It verifies account access to the configured model and requests one short public Tamil answer. It does not test speaker output or your physical microphone. No live provider test was run here.

LIMITS AND OPTIONAL WORK

Voice controls cannot listen while the assistant is speaking; use the existing Stop speaking button to interrupt playback. The word JARVIS is an optional command prefix, not an always-on wake-word engine. Hidden tabs, errors, revoked permissions and manual navigation pause listening. Recognition/TTS availability and autoplay rules vary by browser. If no Tamil output engine exists, errors can only be shown as short status feedback.

Completed advanced items: bounded session memory, context follow-ups, safe page control, published-content retrieval, website fallback, interruption controls and private-data filtering. Persistent bilingual mode, user-adjustable voice/rate/volume, authenticated booking-status voice lookup, booking submission and admin voice actions were not added. Existing secure forms and admin interfaces remain the way to perform those operations. Multi-worker deployment needs a shared expiring context store or sticky sessions; current context is intentionally process-local.
